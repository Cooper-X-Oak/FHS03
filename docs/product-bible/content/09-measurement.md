# 09 度量层 Measurement

度量层定义“怎么知道网站在起作用”：指标口径、埋点、复盘节奏和迭代记录。指标体系见 1.2。

## 9.1 Measurement Plan 度量计划

`已定`

| 指标 | 口径 | 数据来源 | 看的频率 |
| --- | --- | --- | --- |
| **北极星：每月自然搜索有效询盘数** | 来源为自然搜索、级别为 A 或 B（7.4）的询盘数；WhatsApp 和表单都算 | Nina 的询盘记录表 + GA4 | 每月 |
| 收录率 | 已收录页面 ÷ 已提交的 index 页面 | Search Console“网页”报告 | 第 1 个月每周，之后每月 |
| 目标词平均排名 | 每页主关键词（6.2）的平均排名 | Search Console，按“查询 + 页面”筛选 | 每两周 |
| 展示量 | 网页搜索 + 图片搜索分别统计 | Search Console | 每两周 |
| 自然点击 | 来自自然搜索的点击 | Search Console | 每两周 |
| 每页询盘率 | （`whatsapp_click` + `form_submit_success`）÷ 该页自然搜索落地会话 | GA4 | 每月 |
| 询盘有效率 | A + B 级询盘 ÷ 全部询盘 | Nina 的询盘记录表 | 每月 |
| 首次回复时间 | 询盘到 Nina 第一次回复的时间 | Nina 的询盘记录表 | 每月 |

**来源归因**：表单通过隐藏字段记录来源和 UTM；WhatsApp 对话通过预填的页面名识别来源页面，渠道（自然搜索还是主动获客）由 Nina 按 UTM 或对话内容判断。主动获客的流量单独统计，不计入北极星。

### 预期

| 阶段 | 合理预期 | 依据 |
| --- | --- | --- |
| 上线后 1–3 个月 | 以收录和展示为主，询盘零星 | 新站正常节奏 |
| 第一批、第二批成熟后 | 每月几十到一两百个有采购意图的自然访问，带来个位数到十几个询盘 | 最强的中国对手在样本里的核心采购流量也只有每月几百（R7） `分析判断` |

> [!WARNING]
> 这个预期需要提前与 Nina 对齐。网站解决的是“被找到、被放进询价名单”，量不会很大；主动获客是另一条腿。

## 9.2 Tracking Plan 埋点方案

`已定` GA4 事件；前三个标为关键事件。

| 事件 | 触发时机 | 关键事件 |
| --- | --- | --- |
| `whatsapp_click` | 点击任何 WhatsApp 按钮或链接 | 是 |
| `form_submit_success` | **服务器确认**表单提交成功 | 是 |
| `email_click` | 点击邮箱链接 | 是 |
| `form_start` | 第一次在表单中输入 | 否 |
| `form_submit_error` | 提交失败 | 否 |
| `file_attach` | 选择了上传文件 | 否 |
| `part_number_submit` | 替代页型号输入框提交成功 | 否（同时触发 `form_submit_success`） |
| `cta_click` | 点击主按钮（滚动到表单或跳询价页） | 否 |
| `longtail_click` | 点击长尾入口 | 否 |
| `wechat_qr_view` | 微信二维码展开 | 否 |

**所有事件的参数**

| 参数 | 取值 |
| --- | --- |
| `page_id` | IA map 的页面 ID |
| `template` | T1–T10 |
| `entry_location` | `hero`、`mid`、`end`、`sticky`、`longtail`、`nav` |
| `customer_type` | 只在 T6：`distributor`、`integrator` |

在 GA4 中把 `page_id`、`template`、`entry_location` 注册为自定义维度。

**UTM 规则（主动获客）**：`utm_source` = `outbound`；`utm_medium` = `email` / `linkedin` / `whatsapp`；`utm_campaign` = 活动名。获客 agent 发出的所有链接都必须带 UTM，否则会被误算成直接访问。

> [!WARNING]
> 文件内容和留言不传入分析系统。点击不等于对话，前端提交不等于服务器接收成功；有效询盘以 Nina 的记录为准。欧洲访客需要 Cookie 同意，GA4 使用同意模式。

## 9.3 Reporting Cadence 复盘节奏

`已定`

| 时间 | 看什么 | 谁看 |
| --- | --- | --- |
| 每批上线当天 | 记录基线：收录数、展示、点击、询盘（均为 0 也记录） | Cooper |
| 上线后第 1 个月 | 每周看收录 | Cooper |
| 第 2–3 个月 | 每两周看排名、展示、点击 | Cooper |
| 第 3 个月起 | 每月看询盘与有效率；给 Nina 一页月报 | Cooper、Nina |

**月报只放 5 个数**：有效询盘数、全部询盘数、自然点击、收录率、首次回复时间中位数；再加一句“本月改了什么、下月改什么”。

**诊断顺序**（1.2）：

| 现象 | 问题在哪 | 先改什么 |
| --- | --- | --- |
| 上线 4 周收录率 < 80% | 收录 | 内容是否达到 8.4 最低标准；内链；sitemap |
| 有展示、点击率低 | 搜索结果的吸引力 | title、meta description |
| 有点击、没询盘 | 页面转化 | 首屏是否“看到产品”；联系模块；需求提示 |
| 有询盘、有效率低 | 来的人不对 | 关键词意图；页面是否说清服务对象 |
